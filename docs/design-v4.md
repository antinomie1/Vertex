# Vertex 设计 v4 —— 惯性执行范式（在 v3 单设备拓扑上叠加）

> v3 解决"在哪跑"；v4 解决"每帧花多少 CPU 跑"。推翻的是 Iris/VulkanMod/Vitrail 共享的最后一条假设：**命令必须逐帧重录**。

## 0. 观察：体素世界的稳态惯性

飞行探索时，帧与帧之间：
- 可见 section 集合变化极小（视锥缓移）；
- 管线选择不变；顶点缓冲直到重网格化才变；
- 唯一逐帧变化的只有相机矩阵等少量 uniform 数据。

而 Vulkan 提交模型允许：**同一条 primary command buffer 反复提交**（只要不在途并发，需 SIMULTANEOUS 位或每槽副本）。绑定与绘制调用都烘焙在 CB 里——所以真正的约束是：

> **凡是被烘焙进 CB 的东西，都必须跨帧稳定。**

## 1. SSCA：稳态命令摊销（Steady-State Command Amortization）

把绘制路径按"逐帧可变性"切成两类：

| 路径 | 可变性 | 执行方式 |
|---|---|---|
| 不透明地形（含 cutout） | 仅脏事件 | **预录 CB 复用**：脏纪元（可见集变化/重网格/换包）才重录 |
| 静态阴影层 | 太阳角步进+脏集 | 同上，独立 CB |
| 半透明水体排序 | 每帧排序变化 | 逐帧重录（小子集）|
| 实体/粒子/手 | 每帧动态 | 逐帧重录（小子集）|

### 使 CB 可复用的四条纪律（设计约束反推）
1. **禁用 push constants 于摊销路径**（会被烘焙）→ 全部走固定绑定的 uniform heap；
2. **heap 分纪元**：CB 重录时才追加写入，纪元内偏移恒定 → 绘制索引稳定；每 in-flight 槽独立 heap 副本，fence 确认空闲后复用（标准双缓冲语义）；
3. 绑定只含静态 bindless 大数组 + 固定槽位 → 跨帧稳定合法；
4. 视口/剪裁用静态状态或烘焙常量。

### 收益形态
稳态帧的 CPU 录制成本从 **O(可见绘制数)** 降为 **O(脏变更数)**。配合 v3 的批量提交，主线程每帧只剩：脏处理 + 动态子集录制 + 一次 submit。这是对"≥3× OptiFine"承诺的真实加固——飞行场景向 5–10× 逼近有了机制依据（承诺线仍守 3×，不虚标）。

### 与既有组件的耦合
- M3 帧图输出按"纪元稳定性"标注节点：`Amortized` / `PerFrame` 两类；
- M4 几何桥的重网格化事件直接就是脏信号源（天然对齐）；
- 包选项热切换=全量失效纪元（正确性优先）。

## 2. Hi-Z 遮蔽剔除（G3+ 实验，与 SSCA 协同）

- 上一帧深度金字塔做保守遮蔽（相机快速移动时以扩边容错），compute 剔除 → `vkCmdDrawMultiIndexedIndirectCount` 提交；
- 山体自遮挡是 MC 高视距的主要过绘来源，此招直接砍 GPU 侧；
- 与 SSCA 的交互：剔除结果变化=可见集变化=脏纪元 → 二者天然互锁；为避免高频失效，剔除粒度取 section 簇（≥8³ section）而非单体。
- 明确标注：实验特性，默认关，基准确认收益后才转正。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 纪元管理 bug 造成陈旧读取（不可见、难查） | 确定性回放 harness（v3 已升一等公民）逐帧哈希即捕获 |
| heap 双缓冲写读竞争 | 每 in-flight 槽独立 heap + fence 复用（标准语义）|
| SIMULTANEOUS_USE 位 GPU 侧代价（NVIDIA 警告） | 用每槽副本方案规避该位 |
| 半透明/动态路径占比意外的包 | 分层计数器暴露两路径占比，异常包自动退回全量逐帧 |

## 4. 门径增量

- G1 不变（先正确后并行，更先别谈摊销）；
- G2 增项：SSCA 以"仅不透明地形"最小形态落地 + 回放哈希验证；
- G3 增项：静态阴影层并入摊销、Hi-Z 实验、占比计数器看板。

## 5. 三版演进一句话

> v2 在自己地里种；v3 拿到仓库钥匙；**v4 发现庄稼根本不用天天重新种——给田装上记忆，只在变的时候动一下。**

性能叙事随之升级：v2/v3 赢在"提交路径比 Vitrail 干净"；v4 赢在"提交路径比**所有人**都短"——包括 Iris+Sodium，因为它们的 CPU 成本随画面内容线性增长，而 Vertex 稳态下趋近于零。
