# 剩余优化空间盘点（v4 之后，2026-08-25）

## 结论先行
仍有四个实质优化点（合计可再挤 20–60% 视场景），但全部属于"精修"；CPU 提交路径在 SSCA 后已近地板。范式级重构已无——这不是保守，是被三重约束（包语义保真/正确性优先/复杂度预算）夹出的天花板。

## 按性价比排序

### O1. 输入附件自动改写 → 更深融合（中收益/中成本）
检测 composite 程序中对 colortex 的采样是否恰好为 `gl_FragCoord` 对应 texel（单点采样）→ 改写为 `subpassLoad` → 该对 pass 可真融合为单 renderpass 双 subpass。
- 收益估算：每消除一条 pass 边界省一次 colortex 写+读往返；1440p RGBA16F ≈29.5MB，读写≈59MB；6800XT (~512GB/s) ≈0.12ms/边界。重型包几十条边界 → **毫秒级**。
- 判定必须保守：任何非常数偏移/导数采样即放弃该对。
- 来源：`vulkan-subpasses.md` 已预留此路径。

### O2. 引擎原生分辨率缩放（高收益/低成本，用户可见最大杠杆）
gbuffer+composite 链跑 0.5–1.0× 内部分辨率，final 前 FSR1/spiral 缩放回屏。包通过 screenSize uniform 自适应，语义兼容性良好。
- 收益：像素量 ∝ r²。0.75× → 片元成本 ×0.56，GPU 受限场景帧率理论 ×1.5–1.8。
- 前提：阴影图独立分辨率；texel 精确类 pass 在 O1 判定失败时自动排除出缩放链（或整链退 1.0× 并提示）。

### O3. 异步计算 bloom 重叠 + 帧重叠录制（中收益/已排期）
NVIDIA 背书的跨帧重叠模式；v4 后无跨设备信号量拖累。维持 G3 实验位。

### O4. 自有工具 pass 的 DCC 友好化（小收益/顺手）
bloom mip 链等自有 pass 选 vkCmdBlitImage 而非 storage-image 计算写入（后者触发解压，`vulkan-bandwidth-dcc.md`）；RT 全程 attachment 写入保持压缩态。

## 明确封顶的位置（诚实清单）
| 位置 | 为何无空间 |
|---|---|
| 片元数学本身 | 包定义，动=改画面 |
| 半透明排序 | 包混合语义锁死 |
| colortex 格式 | 保真红线，不做"性能化重解释" |
| 动态实体子集 | 本质逐帧，量小 |
| VRS/降质类 | 改观感，拒绝 |

## 终止准则
G0–G3 + O1/O2 落地并基准确认后，转入"测量驱动"模式：只做 profiler 指得出的热点，不再预设计。继续纸面优化的边际收益已低于其正确性风险。
