# Vertex 设计 v3 —— 协同驻留单设备架构（取代 design.md 的拓扑层）
> **➕ 执行层已被 `design-v4.md` 扩展**：SSCA 稳态命令摊销 + Hi-Z 剔除实验。拓扑（单设备协同）不变，v4 在其上叠加。

> 触发：对 v2 七项假设逐一再证伪。六项存活，一项被推翻——而它的替代方案严格优于原案。

## 0. 被推翻的假设："必须第二个 VkDevice"

v2 用双设备 + DMA-BUF 交接（M6），理由是逃离 Blaze3D 的每-pass 全屏障。但屏障在 **Blaze3D 的代码里**，不在设备里。

**v3 核心：劫持设备，而非另建设备。**

- 在 Blaze3D 后端初始化处 mixin 设备创建点，向扩展表与 feature pNext 链注入我们所需（updateAfterBind、timelineSemaphore、multiDrawIndirect、dynamicRendering/sync2——后者游戏大概率已开）。一次性、单点、先于任何使用。
- 此后 Vertex 与 Blaze3D **共用同一 VkDevice/VkQueue**：我们建自己的 command pool/descriptor pool/pipeline/image（同设备多池合法），在"世界渲染后、无打开 pass"窗口内以裸 Vulkan 提交流运行包链，最终色**零拷贝直写**游戏主目标图像。
- 同队列提交按序启动，配合我们提交内部的屏障即完成与 HUD 渲染的衔接；与游戏提交的互斥用锁序约定。

### 收益对照

| 维度 | v2 双设备 | v3 单设备协同 |
|---|---|---|
| 最大风险（跨设备外部内存） | DMA-BUF+信号量 fd，三级退路 | **整体删除** |
| 最终色交接 | 导入导出+所有权转移 | 同设备写目标图像，零拷贝 |
| macOS/MoltenVK | 出局（无 external memory） | **重回候选**（仅受特性注入是否成功约束）|
| 帧延迟 | 跨设备同步开销 | 无 |
| 失败模式 | fd 句柄类型/compositor 组合 | 设备创建点 mixin 断裂（单点，版本耦合与 Vitrail 同量级）|

代价与对策：若注入点断裂→检测不到已启用特性时自动降级为 Tier 0（见 §2），绝不硬崩。

## 1. 存活的六项假设（维持 v2 结论）
Sodium tap（terrain.md 实证）、文本重译→shaderc→SPIR-V、bindless 大数组+NVIDIA 清单反向施工、绑核线程录制纪律、阴影缓存 S3、Kotlin 零分配规范。

## 2. 新增支柱：逐几何族路由 + 三档保真降级

兼容性从"全有或全无"改为**逐族协商**（地形/水/实体/粒子/云/手 各自独立决策）：

| 档位 | 行为 | 触发 |
|---|---|---|
| **Tier 2 全接管** | 该族由我们以包程序绘制 | 族支持且无 mod 冲突 |
| **Tier 1 半接管** | 游戏(经管线短路 mixin)绘制进我们的加宽格式目标，包后续 pass 正常消费（材质 id 缺失，Vitrail 行为）| 族暂不支持 |
| **Tier 0 仅后链** | 游戏正常渲染，我们在世界渲染后挂 composite/final 链 | 特性注入失败/mod 强冲突 |

- 冲突自动降档：检测到异构世界渲染 mod（ReplayMod、DH LOD 注入等）→ 对应族落 Tier 1/0 并日志声明。
- 这把 Vitrail 的"families not yet through the pack"从事后解释升级为**运行时能力协商协议**——mod 兼容性成为可配置的连续谱，而非开关。

## 3. v3 补强点（小但实质）

- **帧重叠录制**（G3+）：T1..Tn 录第 N+1 帧阴影/gbuffer 与第 N 帧 post 链并行——NVIDIA 官方背书的跨帧重叠模式；单设备后无跨设备信号量拖累，落地成本大降。
- **确定性回放测试升为一等公民**（testkit）：固定种子+脚本相机+逐帧哈希，驱动升级/编译器变更的 CI 回归基线；截图差分只是其可视化形态。
- **翻译产物磁盘缓存共享化**：按（源哈希+选项哈希+driverID）键控的 SPIR-V 缓存目录可手动导入导出（热门包二次启动近零编译）；线上共享缓存列为远期（注意许可：只分发译文不分发原包）。
- **拒绝项记录**：GPU 驱动网格化/meshlet 管线（体素顶点量级不需要，复杂度不成比例）、自研网格器（放弃 Sodium 生态=自杀）、干净室前端（放弃 Iris 语料=自杀）。

## 4. 对门径的影响

| 门 | v2 内容 | v3 修订 |
|---|---|---|
| G0 | 双设备三角形+DMA-BUF 闭环 | **设备创建点注入验证**：扩展/特性注入成功→同设备裸 Vulkan 三角形直写主目标可见。验收含"注入失败→Tier 0 自动降级"路径 |
| G1 | 不变 | 不变（单设备使 G1 更薄）|
| G2 | 兼容冲刺 | + 逐族协商协议落地与降档矩阵测试 |
| G3 | 性能四连 | + 帧重叠录制实验 |

## 5. 一句话版本

> v2 是"在自己地里种庄稼，收成运回对方仓库"；v3 是"拿到对方仓库的钥匙，就地入库"。删掉的是整条物流线（M6），换来的是零拷贝、更低延迟、macOS 生还和更薄的 G0。
